## 2. 전반적인 작동 방식 (단일 페이지 애플리케이션 - SPA)
현재 서비스는 페이지 이동 없이 한 화면에서 모든 것이 이루어지는 **SPA(Single Page Application) 방식**으로 구현되어 있습니다. 

- **중앙 통제실 (`page.tsx`):** 사용자가 보는 화면(우리의 벽, 오늘의 선행), 팝업 모달창, 데이터 불러오기 등 모든 핵심 동작이 `src/app/page.tsx` 한 곳에서 통합적으로 관리됩니다. 
- **화면 깜빡임 없음:** '우리의 벽' 탭과 '오늘의 선행' 탭을 오갈 때마다 새로고침이 발생하지 않습니다. 이미 받아온 전체 데이터를 바탕으로, 보여줄 내용만 즉각적으로 껐다 켰다(필터링) 하는 방식이라 속도가 매우 빠릅니다.

## 3. 데이터는 어떻게 흐르는가? (프론트엔드 ↔ 백엔드 ↔ DB)

### ① 선행 글 작성 (포스트잇 붙이기)
1. 사용자가 화면 하단의 `+` 버튼을 눌러 모달창을 열고 글귀, 태그, 색상을 선택합니다.
2. '완료'를 누르면 프론트엔드가 백엔드 API (`POST /api/posts`)로 이 데이터를 쏩니다.
3. 백엔드는 이 데이터를 받아 `data/warmth_wall.db` (SQLite 데이터베이스)의 `posts` 테이블에 영구 저장합니다.
4. 저장이 끝나면 화면을 즉시 새로고침하여 방금 작성한 내 포스트잇이 화면 맨 앞에 나타나게 합니다.

### ② "나도요" (공감하기) 버튼의 원리 (Optimistic UI)
"나도요" 기능은 사용자 경험(UX)을 극대화하기 위해 특별한 기법이 적용되어 있습니다.
1. **눈속임 (즉각 반응):** 사용자가 '나도요'를 클릭하는 순간, 백엔드 응답을 기다리지 않고 **화면상의 숫자부터 1을 즉시 올리고 까만색 뱃지로 색상을 바꿔버립니다.** (마치 바로 된 것처럼 빠릿하게 느낌)
2. **실제 처리 (백그라운드):** 그 직후 뒤에서 조용히 API (`POST /api/posts/[id]/repost`)를 호출하여 진짜 DB에 "이 유저가 이 글에 나도요를 눌렀음" 이라는 데이터를 저장합니다. 

### ③ 탭 필터링 ('우리의 벽' vs '오늘의 선행')
- **우리의 벽:** DB에 있는 모든 포스트잇 데이터를 시간순으로 전부 뿌려줍니다.
- **오늘의 선행:** 별도로 백엔드에 요청하지 않습니다. 이미 불러온 전체 데이터 중에서 **"내가 쓴 글(`isOwn === true`)이면서 동시에 오늘 작성된 글(`date === 오늘`)"** 인 것들만 추려내서(Filter) 화면에 보여줍니다.

## 4. 핵심 기술 및 상태 관리 (State Management)

- **상태 관리 (React `useState`):** 
  앱 내의 모든 유동적인 데이터는 React의 상태 관리 훅을 사용합니다.
  예를 들어 `activeTab = 'public' | 'today'` 상태를 두어, 이 값이 바뀔 때마다 보여주는 화면 컴포넌트(`PublicTab` ↔ `TodayTab`)를 통째로 교체합니다.
- **타이머와 애니메이션 (`useEffect`):**
  - 상단 전광판(AI 브리핑 배너)의 글씨가 스르륵 지나가는 효과
  - 몇 분 전, 몇 시간 전 등 상대적 시간을 계산하는 로직 등은 모두 `useEffect`를 통해 지속적으로 동기화됩니다.

## 5. 향후 인공지능(AI) 확장성

현재 백엔드 DB(`warmth_wall.db`)에는 사용자가 작성한 **'순수 텍스트(선행 내용)'**와 **'작성 시간'**, **'선택한 태그'**가 훼손 없이 원본 그대로 정규화되어 저장되고 있습니다.

이는 향후 **Gemini API**와 같은 생성형 AI를 붙일 때 엄청난 강점이 됩니다.
- **AI 기반 태그 자동 분류:** 사용자가 글만 대충 써도, AI가 문맥을 분석하여 알맞은 카테고리 뱃지를 자동으로 달아주는 기능.
- **주간/월간 리포트 생성:** DB에 쌓인 일주일치 텍스트 데이터를 AI에게 던져주면, "다솜님은 이번 주에 특히 환경을 아끼는 배려를 많이 하셨네요!" 와 같은 개인화된 감동 리포트를 즉시 찍어낼 수 있습니다.
